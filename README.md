1. Описание проекта

В рамках данного проекта разрабатывается программа для обезличивания CIM-моделей энергосистем, которые представлены в формате XML.
Такие модели содержат много разной информации: названия подстанций, линий электропередачи, данные абонентов, сотрудников и технические характеристики объектов. Использовать реальные данные в тестовых проектах и при разработке программ не всегда безопасно, так как по ним можно узнать личную информацию людей или получить сведения об объектах энергетической инфраструктуры
Поэтому главная задача нашей программы — заменить реальные названия и другие конфиденциальные данные на искусственные, при этом по возможности сохранить исходную структуру XML-файла и связи между объектами.
Отдельно стоит отметить, что программа рассчитана на работу с большими XML-файлами. Согласно техническому заданию, их размер может достигать нескольких гигабайт, поэтому при разработке важно было выбрать способ обработки, который не требует загрузки всего файла в оперативную память.

2. Как работает программа

Программа написана на Python. Для обработки XML используется библиотека `xml.sax`, которая позволяет читать документ постепенно, по мере поступления данных.
Сначала программа подключается к Google Drive, где находится исходный файл `input.xml`. После этого загружаются подготовленные списки, которые используются для создания новых названий. В программе есть три таких списка: имена, фамилии и названия фруктов и овощей.
Основная обработка происходит в классе `CIMAnonymizer`. Он отвечает за чтение XML-документа и запись обработанных данных в новый файл.
Для этого используются три события XML-парсера:

- `startElement` — срабатывает, когда программа встречает начало XML-элемента;
- `characters` — отвечает за чтение текста внутри элемента;
- `endElement` — срабатывает при завершении элемента.

В нашей реализации основное внимание уделяется элементу `cim:IdentifiedObject.name`, в котором хранятся названия объектов и другие имена.
Когда программа встречает такой элемент, она передаёт его содержимое функции `get_fake_name()`. Эта функция определяет, какое именно синтетическое название нужно использовать.
Для распознавания энергетических объектов программа проверяет исходное название на наличие определённых слов и обозначений: `grid`, `network`, `center`, `substation`, `office`, `rdo`, `res`, `пс`, `тп` и `лэп`.
Если в названии обнаруживается одно из этих обозначений, программа выбирает случайное название из списка фруктов и овощей и добавляет к нему слова `electrical network`. Например, вместо реального названия можно получить «Абрикос electrical network» или «Банан electrical network».
Если название не подходит под эти условия, программа формирует другое значение — случайную комбинацию фамилии и имени из подготовленных списков. Например, «Иванов Анна» или «Петров Мария».
Чтобы одинаковые исходные названия не заменялись каждый раз по-разному, используется словарь `mapping_dict`. В нём сохраняются все созданные соответствия между исходными и новыми значениями. Если программа уже встречала какое-то название, она использует ранее созданную замену. Это позволяет сохранить единообразие названий в пределах одного запуска.
После обработки программа записывает результат в отдельный файл `output_anonymized.xml`. При этом XML-теги и их атрибуты переносятся в новый документ, а выбранные текстовые значения заменяются на синтетические.

3. Используемые технологии

Для создания программы использовались следующие инструменты:

- Python — основной язык программирования, на котором написано решение.
- xml.sax — библиотека для последовательной обработки XML-файлов.
- random — используется для случайного выбора имён, фамилий и названий из подготовленных списков.
- os — помогает проверить наличие исходного файла.
- Google Colab — среда, в которой запускается программа.
- Google Drive — используется для хранения исходного и полученного XML-файлов.

Выбор Python связан с тем, что он достаточно удобен для работы с файлами и структурированными данными, а также позволяет при необходимости добавлять новые функции и улучшать уже существующие.

4. Особенности нашего решения

Одной из главных особенностей программы является использование потоковой обработки. Благодаря `xml.sax` документ не нужно полностью загружать в оперативную память. Программа читает его постепенно, обрабатывает нужные элементы и сразу записывает результат в выходной файл. Это особенно важно при работе с большими CIM-моделями.
Также мы разделили обработку XML и генерацию новых названий. За создание синтетических значений отвечает отдельная функция, а за чтение и запись XML — специальный класс. Благодаря этому в дальнейшем будет проще добавлять новые правила обезличивания.
Ещё одна особенность — использование словаря соответствий. Он помогает не создавать разные названия для одного и того же исходного значения в пределах одного запуска программы.

5. Результат работы

После запуска программы создаётся новый файл `output_anonymized.xml`, в котором выбранные исходные названия заменены синтетическими.
В результате тестового запуска был получен XML-файл размером примерно 1,16 ГБ. Это показывает, что разработанный механизм удалось применить к достаточно большому документу.
Вместо реальных названий энергетических объектов в файле встречаются, например, «Абрикос electrical network», «Груша electrical network» и «Банан electrical network». Другие обрабатываемые названия заменяются комбинациями искусственных имён и фамилий.
При записи результата программа сохраняет XML-теги и переносит атрибуты исходного документа. Ссылки между объектами, указанные через `rdf:resource`, также переносятся без изменения.
Таким образом, в результате получается отдельная версия исходной модели, в которой часть реальных наименований заменена искусственными значениями.

7. Итог
В ходе работы был разработан прототип программы для обезличивания CIM-моделей энергосистем. Он позволяет обрабатывать XML-файлы с помощью потокового парсера, находить определённые наименования и заменять их на искусственные значения.
Главная особенность решения заключается в том, что оно может работать с большими XML-документами без необходимости полностью загружать их в оперативную память. Полученный результат представляет собой отдельный XML-файл, в котором часть исходных наименований заменена синтетическими.

Разработанная программа пока не охватывает все категории данных, указанные в техническом задании, однако уже показывает основной принцип работы будущей системы. В дальнейшем её можно расширить, добавив обезличивание персональных данных, цифровых идентификаторов, координат и других конфиденциальных сведений.

В итоге наше решение может стать основой для инструмента, который позволит безопаснее использовать CIM-модели при разработке, тестировании и демонстрации программных продуктов.
